# CodingBot 0.8.0 — risky_tool 차단 hook 통합 e2e

작성일: 2026-05-02
베이스: `v0.7.0`
사이클 가치: **A — 신뢰성 검증 자동화** (0.5.0 hook 통합 e2e 트랙 확장)

---

## §1 동기

0.2.0에서 도입한 bash segment 기반 위험 분류(secret/install/priv + chain bypass 차단)는 `tests/unit/test_heuristics.py`에서 ~41건의 unit으로 증명되어 있다. 그러나 다음 통합 경로는 e2e_auto에 빈 칸이다:

```
heuristics.classify_tool_call("Bash", {"command": "cat .env"}) == "risky"
   ─►  hooks.auto_approve subprocess가 실제로 _defer_to_user로 분기
       ─►  stdout 빈 출력 (Claude Code가 사용자 승인을 받게 함)
       ─►  state.auto_defer_by_heuristic 카운터 +1
```

unit pass ≠ subprocess pass라는 교훈은 0.5.0(S5~S8)에서 이미 학습됨. 0.5.0은 **judge 분기**(timeout/error)만 e2e로 증명했고, **heuristic risky 분기**는 미증명. 0.8.0은 그 공백을 메운다.

## §2 결정 요약

- 운영 코드 **변경 없음**. 0.4.0/0.5.0과 같은 결: 테스트만 추가.
- 신규 시나리오 5건(S9~S13)을 기존 `tests/e2e/test_hook_integration.py`에 합류. 별도 파일 분리하지 않음(같은 트랙 — hook subprocess 통합).
- 픽스처 신규 추가 없음. `hook_env`, `transcript_jsonl_factory`, `tmp_codingbot_home` 재사용.
- API 키 / fault-inject 불필요. heuristic risky 분기는 llm_judge 미호출 경로(`auto_approve.py:55-57`).
- judge 캐싱 / 새 카운터 / runner 통합은 비범위.

## §3 시나리오 명세

각 시나리오는 독립 함수. `pytestmark = pytest.mark.e2e_auto` 상속. `tmp_codingbot_home` 픽스처로 state 격리.

### §3.1 S9 — secret_segment_blocked

| 항목 | 값 |
|---|---|
| stdin `tool_name` | `Bash` |
| stdin `tool_input` | `{"command": "cat .env"}` |
| 분류 경로 | `_classify_bash` → `_is_secret_segment(["cat", ".env"])` 매치(`_SECRET_FILE_PATTERNS[0]`) → `risky` |
| 단언 | `exit_code == 0`, `decision is None`, `auto_defer_by_heuristic == 1`, `judge_call_total == 0` |

### §3.2 S10 — install_segment_blocked

| 항목 | 값 |
|---|---|
| stdin `tool_input` | `{"command": "pip install requests"}` |
| 분류 경로 | `_is_install_segment(["pip", "install", "requests"])` → True → `risky` |
| 단언 | S9와 동일 패턴 |

### §3.3 S11 — priv_segment_blocked

| 항목 | 값 |
|---|---|
| stdin `tool_input` | `{"command": "sudo rm /tmp/x"}` |
| 분류 경로 | `_is_priv_segment(["sudo", "rm", "/tmp/x"])` → argv[0] == "sudo" → True → `risky` |
| 단언 | S9와 동일 패턴 |

### §3.4 S12 — chain_bypass_still_blocked

| 항목 | 값 |
|---|---|
| stdin `tool_input` | `{"command": "echo ok && cat .env"}` |
| 분류 경로 | `_split_bash_segments` → `[["echo","ok"], ["cat",".env"]]` → 두 번째 segment에서 `_is_secret_segment` True → `risky` |
| 단언 | S9와 동일 패턴 |
| 주석 | **0.2.0의 핵심 보안 주장**: 첫 segment가 안전해도 chain 내부의 위험 segment를 잡는다 |

### §3.5 S13 — safe_bash_still_approves (대조)

| 항목 | 값 |
|---|---|
| stdin `tool_input` | `{"command": "ls"}` |
| 분류 경로 | `_classify_bash` → secret/install/priv 미매치 → `_seg_is_safe_prefix(["ls"])` True(_SAFE_BASH_PREFIXES) → `safe` |
| 단언 | `exit_code == 0`, `decision == {"decision": "approve", "reason": ...}`, `auto_approve_count == 1`, `auto_approve_by_heuristic == 1`, `auto_defer_by_heuristic == 0` |

### §3.6 공통 입력

- `transcript`: `transcript_jsonl_factory([{"role":"assistant","text":"임의"}])` — heuristic risky 분기는 transcript를 읽지 않으므로 내용 무관.
- `env`: `hook_env()` 기본값(`CODINGBOT_FAULT_INJECT` 미설정).

## §4 아키텍처 / 데이터 흐름

```
pytest_test_s9
  │
  ▼
run_pre_tool_use(stdin_dict, env)         (tests/e2e/hook_harness.py)
  │
  ▼ subprocess: python -m codingbot.hooks.auto_approve
  │
  ├─ heuristics.classify_tool_call(tool_name, tool_input)   ── verdict ∈ {safe, risky, unknown}
  │
  ├─ verdict == "risky"  →  _defer_to_user(reason, "heuristic")
  │                          → state.record_auto_defer_by("heuristic")     # +1
  │                          → (no stdout)
  │
  ├─ verdict == "safe"   →  _approve(reason, "heuristic")
  │                          → state.record_auto_approve()                  # +1 (legacy)
  │                          → state.record_auto_approve_by("heuristic")    # +1
  │                          → print(json.dumps({"decision":"approve",...}))
  │
  └─ verdict == "unknown" → judge 분기 (이 spec 비범위 — S6~S8이 cover)
  │
  ▼
HookResult(exit_code, stdout, stderr)
  │
  ▼
state.read()  → 카운터 단언
```

운영 코드 무변경. state schema 무변경. 의존 그래프 무변경.

## §7 리스크 / Drift

- **R1 — `_classify_bash` segment 분리 로직 변경**: S12가 첫 신호. 회귀 알람 자체가 가치 → 수용.
- **R2 — `_SAFE_BASH_PREFIXES`에서 "ls" 제거**: S13 fail. 동일 이유로 수용.
- **R3 — state 카운터 키(`auto_approve_by_heuristic`, `auto_defer_by_heuristic`) 변경**: 모든 e2e fail. 의도적 — state schema 변경은 e2e가 강제로 알려야 함.
- **R4 — Windows shell quoting**: subprocess `text=True`로 stdin은 stdout과 동일 인코딩. `.env`는 ASCII이므로 영향 없음.
