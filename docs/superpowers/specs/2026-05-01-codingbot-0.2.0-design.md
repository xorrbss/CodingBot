# CodingBot 0.2.0 — 신뢰성/안전성 사이클 설계

- 작성일: 2026-05-01
- 베이스: `v0.1.2` (commit `cb2385b`)
- 사이클 가치 분류: **A — 신뢰성/안전성**
- 범위: A2(위험 패턴 감지 강화) + A3(실패 fallback 정공 정리, 실제 갭에 한정)
- 비범위: A1 e2e 시나리오 확장(0.3.0/D 사이클로), A4 property-based 다양화, B/C/D 사이클 항목

## 1. 동기

0.1.x 사이클은 transcript schema 정공법과 같은 기반 정확성에 집중했다. 0.2.0은 그 기반 위에서 **자동 결정의 안전망**을 강화한다. 사용자가 명시한 우려:

1. (a) 시크릿 누출 — `.env`, ssh key, aws creds, env dump
2. (c) 패키지/시스템 변경 — `pip|npm|apt|brew|choco|winget|...` install
3. (d) 권한 상승 — `sudo`, `chmod 777`, `chown root`
4. (f) 우회 패턴 — pipe, sub-shell, chain operator로 위험 segment 숨기기

현재 `heuristics.py`는 substring 매칭이라 (f)에 본질적으로 취약하다. (a)/(c)/(d) 패턴은 일부만 `risky_patterns`(예: `rm -rf`, `git push --force`)에 들어가 있고 카테고리화돼 있지 않아 사용자 확장이 어렵다.

A3는 코드 점검 결과 대부분 이미 처리되어 있고(`config.py:52-54`, `state.py:27-29`, `transcript.py` skip+warn), **실제 갭**은 두 곳뿐이다: `llm_judge` timeout 부재, `runner` claude CLI 부재 처리. 이 두 가지만 닫고 나머지는 회귀 테스트로 codify한다.

## 2. 핵심 결정

| 항목 | 결정 |
|---|---|
| Bash 명령 평가 방식 | shlex 기반 segment 분해 후 segment별 카테고리/legacy 매칭 (정공법) |
| 카테고리 종류 | secret / install / priv (chain 우회는 segment 분리로 자동 해소되어 별도 카테고리 불필요) |
| 외부 인터페이스 | `classify_tool_call` 시그니처 변경 없음 (KISS, 변경 최소화) |
| 모듈 분리 | 새 모듈 도입 안 함 — `heuristics.py`(현재 103 LOC) 안에서 정리 (≤ 500 LOC 룰 안전) |
| `risky_patterns` 호환 | 유지. 카테고리는 추가 레이어 |
| `llm_judge` timeout | `cfg.judge_timeout_secs` 신규, default `15`. Anthropic SDK `timeout=` 인자에 전달 |

| 로그 일관성 | 기존 `auto_approve` / `auto_defer_to_user` 로깅이 충분. 변경 없음 |

## 3. 컴포넌트 변경 명세

### 3.1 `heuristics.py` — bash 파싱 + 카테고리 검사

#### 3.1.1 `_split_bash_segments(cmd: str) -> list[list[str]] | None` (신규 private)

Bash 명령을 평가 가능한 sub-command 단위로 분해.

**알고리즘**:
1. `shlex.split(cmd, posix=True)`로 토큰화 (quoting 보존)
2. chain operator(`;`, `&&`, `||`, `|`)에서 segment 분할
3. command substitution(`$(...)`, backtick) 안의 명령은 별도 segment로 추출
4. process substitution(`<(...)`), redirection(`>`), heredoc은 본 사이클 범위 외 — 발견 시 segment를 그대로 두고 후속 매칭에서 `unknown`으로 떨어지게 함 (안전한 폴백)
5. `shlex` 파싱 실패(quote 불일치 등) → `None` 반환 → 호출자는 `unknown`으로 매핑

**예시**:

| 입력 | 결과 |
|---|---|
| `git status && git diff` | `[["git","status"], ["git","diff"]]` |
| `echo "; rm -rf /"` | `[["echo","; rm -rf /"]]` (quoting 보존, 단일 segment) |
| `safe; sudo rm -rf /` | `[["safe"], ["sudo","rm","-rf","/"]]` |
| `result=$(curl http://x)` | `[["result="], ["curl","http://x"]]` |
| `echo "x` (불일치 quote) | `None` |

#### 3.1.2 카테고리 매처 (신규 private 함수들)

```python
def _is_secret_segment(argv: list[str]) -> bool: ...
def _is_install_segment(argv: list[str]) -> bool: ...
def _is_priv_segment(argv: list[str]) -> bool: ...
```

**secret 패턴**:
- 파일명/경로: `.env`(.env, .env.local 등), `id_rsa|id_ed25519|id_ecdsa|id_dsa`, `.aws/credentials`, `.aws/config`, `.npmrc`, `.pypirc`, `.netrc`
- 환경 변수 dump: `argv[0] in {printenv, env, set}`
- 시크릿 이름 hint: argv 내 `\$.*?(API[_-]?KEY|SECRET|TOKEN|PASSWORD)`

매치 시 즉시 `True`.

**install 패턴**:
- `argv[0]`이 패키지 매니저 + `argv[1]`이 install 류일 때만 `True`
- 매니저: `pip|pip3|pipx|npm|yarn|pnpm|apt|apt-get|brew|choco|winget|scoop|gem|cargo`
- 서브커맨드: `install|add|i|upgrade|update`
- `pip list`, `npm view` 등 read-only는 `False`
- 특수: `go install` (argv[0]=go, argv[1]=install)

**priv 패턴**:
- `argv[0] in {sudo, runas, doas, su}` → `True`
- `argv[0] == "chmod"` 이고 인자에 `777` 또는 `\+x.*?(/|\$)` → `True`
- `argv[0] == "chown"` 이고 인자에 `root` 또는 `0:` → `True`
- `argv[0] in {setcap, setuid}` → `True`

#### 3.1.3 `_classify_bash` 흐름 변경

의사코드:

```
segments = _split_bash_segments(cmd)
if segments is None:
    return "unknown"

# 1) 카테고리 검사 — 어느 segment 하나라도 매칭되면 risky
for category in ("secret", "install", "priv"):
    if cfg.risky_categories.get(category, True):
        if any(_is_<category>_segment(argv) for argv in segments):
            return "risky"

# 2) legacy risky_patterns — segment 문자열 표현에 substring 매칭
for argv in segments:
    seg_str = " ".join(argv)
    if any(p in seg_str for p in cfg.risky_patterns):
        return "risky"

# 3) safe — 모든 segment가 _SAFE_BASH_PREFIXES 중 하나라도 만족
def _seg_is_safe(argv) -> bool:
    seg_str = " ".join(argv)
    return any(seg_str == p.rstrip() or seg_str.startswith(p)
               for p in _SAFE_BASH_PREFIXES)
if all(_seg_is_safe(argv) for argv in segments):
    return "safe"

return "unknown"
```

(실제 구현 시 헬퍼 분리. 위는 의도만 표현.)

### 3.3 `llm_judge.py` — timeout + 에러 체인

```python
def _call(system: str, user: str) -> str:
    cfg = config.load()
    try:
        resp = _client().messages.create(
            model=cfg.judge_model,
            max_tokens=300,
            timeout=cfg.judge_timeout_secs,   # 신규
            system=system,
            messages=[{"role": "user", "content": user}],
        )
    except Exception as e:
        raise JudgeError(f"API call failed: {e}") from e   # from e 추가
    ...
```

`_call` 내 모든 `raise JudgeError(...)`에 `from e` 일관 적용.

### 3.4 `runner.py` — claude CLI 부재 처리

```python
def run(initial_prompt: str) -> int:
    """
    Returns: 종료 코드
      0 = 정상
      1 = 락 충돌
      2 = Claude Code 연속 비정상 종료
      3 = 환경 오류 (claude CLI 부재 등)
    """
    if shutil.which("claude") is None:
        logger.error("env_error", reason="claude_cli_not_found")
        print(
            "[codingbot] claude CLI를 PATH에서 찾을 수 없습니다. "
            "Claude Code를 설치하거나 PATH를 확인하세요.",
            file=sys.stderr,
        )
        return 3
    # ...기존 로직...
```

### 3.5 `cli.py` — exit code propagation 확인

`cli.py`의 `run` 명령은 0.1.x에서 runner의 return code를 그대로 `sys.exit()`하도록 정리됨(`7f80344` M-5). 따라서 새 코드 `3`도 자동 propagate. 구현 시점에 1줄로 확인만 하고 변경 없으면 종료.

## 4. 데이터 흐름

```
PreToolUse hook 입력 (tool_name, tool_input)
    │
    ▼
classify_tool_call(tool_name, tool_input)
    │
    ├─[non-Bash]→ safe_tools / risky_patterns(flat) → safe|risky|unknown
    │
    └─[Bash]→ _classify_bash(cmd)
              │
              ▼
         _split_bash_segments(cmd) → list[list[str]] | None
              │                          │
              │                          └─ None → "unknown"
              ▼
         segment loop:
           ├─ category match (secret/install/priv) → "risky"
           ├─ legacy risky_patterns → "risky"
           ▼
         all segments safe-prefix → "safe", else "unknown"
    │
    ▼
hook 결정:
    safe → approve (heuristic)
    risky → defer (heuristic)
    unknown → llm_judge.evaluate_tool_safety
              ├─ 성공: approve | ask
              └─ JudgeError(timeout 포함) → defer (llm_failed)
```

## 5. 에러/실패 정책

| 위치 | 실패 모드 | 정책 | 상태 |
|---|---|---|---|

- 사용자 추가 패턴 (`risky_categories.secret: ["my_pattern"]`) — **descope** (KISS, default 패턴이 충분하다 가정. user request 시 0.3.0 검토)
