# CodingBot 0.7.0 — `serve` (W 사이클: 로컬 웹 대시보드) 설계

- 작성일: 2026-05-01
- 베이스: `v0.6.0`
- 사이클 가치 분류: **W — 운영 가시성 확장 (브라우저 한 화면에서 라이브 + 시계열)**
- 범위: `codingbot serve [--port N] [--host H] [--no-browser]` — 로컬 read-only 웹 대시보드. stdlib `http.server` + 클라이언트 폴링 + vanilla HTML/JS + inline SVG. `~/.codingbot/state.json`과 `log.jsonl`만 읽는다.
- 비범위: 인증/원격 노출, 쓰기 API, WebSocket/SSE, 차트 라이브러리 의존, 멀티 codingbot 인스턴스 집계, 로그 검색/필터 UI, 알림 (소리/desktop notify).

## 1. 동기

0.6.0 `status --watch`는 한 터미널 화면에서 라이브를 80% 충족시켰다. 그러나 다음이 비어있다:

1. **시계열**: judge call/timeout/error의 추세가 안 보인다 (현재값만 본다).
2. **시각적 분리**: counter/timeline/log이 모두 ASCII로 흘러내려 한 눈에 잡기 어렵다.
3. **stop signal/lock 변동의 즉시 인지**: alert가 다른 카운터와 동등한 라인에 묻힌다.

W 사이클 목표: **브라우저 한 화면에서 카운터, judge 시계열, last log, lock/stop alert를 동시에 본다.** 추가 의존 0개. 로컬 read-only.

## 2. 핵심 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 서버 | `http.server.ThreadingHTTPServer` + `BaseHTTPRequestHandler` | stdlib. 의존 0. 동시 폴링 핸들이 1자리수 → threading으로 충분. asyncio/uvicorn은 가치 대비 비용 과대. |
| 클라이언트 푸시 | 불사용. 클라이언트가 polling | KISS. SSE는 클라이언트 reconnect/buffer 처리, WS는 라이브러리 또는 추가 핸드셰이크. polling 1~5s는 운영자 1명 시나리오에 충분. |
| 프론트 stack | 단일 `index.html` + vanilla JS + inline SVG | 빌드 step 0. npm/webpack 0. CSP는 `default-src 'self'`로도 충분. |
| static 패키징 | `codingbot/static/index.html` + `importlib.resources`로 read | 0.6.0까지의 패키지 레이아웃과 일관. 설치 시 `package_data`/wheel에 포함. |
| 데이터 소스 | `state.json` + `log.jsonl` 만 read | 새 schema/저장소 0. 0.6.0 invariant 유지. |
| API 포맷 | JSON | 표준. JS `fetch().then(r=>r.json())`. |
| 종료 | Ctrl-C → server shutdown → rc 0 | `KeyboardInterrupt` catch. lock file 영향 없음 (serve는 runner와 다른 lock 사용 안 함). |
| browser 자동 오픈 | default ON, `--no-browser`로 끔 | 운영자 시나리오는 "켰을 때 바로 본다"가 우세. CI/headless 회피용 옵트아웃 제공. |
| port | default 8723, `--port N` override | 8000/8080 충돌 회피. 사용 중이면 명시적 에러 후 rc 1. |
| host | default `127.0.0.1`, `--host H` override | 보안 기본값. `0.0.0.0`은 명시적 옵트인. |
| timeline window | 30분, 60초 bucket = 30 point | `log.jsonl` linear scan. 10분 미만/2시간 초과는 0.7.x 폴리시. |
| polling 주기 | `state` 1s / `log/tail` 2s / `timeline` 5s | 변동성 비례. 서버 부하·UX trade-off의 KISS 디폴트. |

## 3. 컴포넌트 명세

### 3.1 `codingbot/serve.py` (신규, 목표 ≤ 250 LOC)

#### 3.1.1 진입

```python
def run_serve(host: str, port: int, open_browser: bool) -> int:
    server = ThreadingHTTPServer((host, port), _Handler)
    if open_browser:
        threading.Thread(target=_open, args=(host, port), daemon=True).start()
    print(f"[codingbot] serving on http://{host}:{port}  (Ctrl-C to stop)")
    try:
        server.serve_forever()
    except KeyboardInterrupt:
        server.shutdown()
        return 0
```

- port 충돌: `OSError(EADDRINUSE)` → stderr `[codingbot] port {port} in use`, rc 1.

#### 3.1.2 핸들러 라우트

| GET path | 응답 | 캐시 |
|---|---|---|
| `/` | `index.html` 내용 (`text/html; charset=utf-8`) | no-cache |
| `/static/<file>` | `codingbot/static/<file>` 화이트리스트 (예: `app.js`, `app.css`만 추가될 때) | no-cache |
| `/api/state` | `state.read()` JSON dump + `{"lock_pid": int|null, "stop_signal": bool, "ts": iso8601}` | no-cache |
| `/api/log/tail?n=50` | `_read_log_tail(n)`의 raw 라인을 `{"lines": [str, ...]}` | no-cache |
| `/api/timeline?window=1800` | `_compute_timeline(window_sec)` → `{"buckets": [{"t": iso8601, "judge_call": int, "judge_timeout": int, "judge_error": int}, ...]}` | no-cache |
| 그 외 | 404 plain text | — |

- path traversal 가드: `/static/<file>`은 정규식 `^[a-zA-Z0-9._-]+$`로 매칭. 매칭 실패 = 404.
- `<file>`이 존재하지 않으면 404.
- 메서드: GET 외 405.

#### 3.1.3 신규 헬퍼

```python
def _read_lock_pid() -> Optional[int]:
    p = paths.lock_file()
    if not p.exists():
        return None
    try:
        return int(p.read_text(encoding="utf-8").strip())
    except (ValueError, OSError):
        return None

def _read_stop_signal() -> bool:
    # 0.5.0의 stop signal 판정과 동일 경로 재사용
    return paths.stop_signal_file().exists()

def _compute_timeline(window_sec: int, bucket_sec: int = 60) -> List[dict]:
    """log.jsonl을 한 번 read, ts 기준 ≥ now-window 라인만 60초 bucket으로 집계.
    judge_call / judge_timeout / judge_error 3 메트릭. 빈 bucket도 0으로 채움."""
```

- `_compute_timeline`이 본 이벤트 매핑:
  - `judge_call`: `event in {"auto_approve", "auto_defer_to_user", "stop_hook"}` 중 LLM judge 호출이 발생한 케이스 (`fields.judge="llm"`).
  - `judge_timeout`: `event == "llm_timeout"`.
  - `judge_error`: `event == "llm_api_error"`.
- 명시적 `judge=*` 필드가 없는 이벤트는 휴리스틱(heur)로 간주, judge_call에 포함하지 않음.
- 잘못된 라인(JSON parse 실패): 무시.

#### 3.1.4 정적 자원 로드

```python
from importlib.resources import files

def _load_static(name: str) -> Optional[bytes]:
    pkg = files("codingbot.static")
    target = pkg / name
    if not target.is_file():
        return None
    return target.read_bytes()
```

### 3.2 `codingbot/static/index.html` (신규, 목표 ≤ 300 LOC)

- 단일 파일. `<style>` + `<script>` 인라인.
- Layout B 적용:
  - 상단: sticky alert bar (lock pid + stop signal + 갱신 시각). lock 없거나 stop_signal=false면 상태 라인 톤만 약화 (숨김 X).
  - 좌 컬럼: counters cards (Cycle, PreToolUse, Stop). 30~40% 폭.
  - 우 컬럼: judge timeline SVG (sparkline-style 30 bucket bar) + last log scroll. 60~70% 폭.
- JS:
  - `setInterval(fetchState, 1000)`, `fetchLogTail, 2000`, `fetchTimeline, 5000`.
  - fetch 실패: alert bar에 "disconnected" 톤 추가, 다음 tick에 재시도.
  - SVG: 60×30 viewBox, 30 bar, height = `min(value/max, 1)*100%`. judge_call=녹/timeout=주황/error=빨강 stacked.
- CSS: monospace font, 다크 배경 옵션 prefers-color-scheme.

### 3.3 `codingbot/cli.py` 변경 (목표 +10 LOC)

```python
def _cmd_serve(args: argparse.Namespace) -> int:
    from .serve import run_serve
    return run_serve(args.host, args.port, not args.no_browser)

# subparser
serve = sub.add_parser("serve", help="로컬 웹 대시보드 시작")
serve.add_argument("--host", default="127.0.0.1")
serve.add_argument("--port", type=int, default=8723)
serve.add_argument("--no-browser", action="store_true")
serve.set_defaults(func=_cmd_serve)
```

- import는 함수 내부 (CLI 부팅 시간 무영향).

## 6. 비범위 (명시)

- **인증/원격 노출**: default `127.0.0.1`. `--host 0.0.0.0`은 사용자 책임. HTTPS/auth 0.7.x 외.
- **쓰기 API**: 모든 endpoint GET. 모니터링 only.
- **WS/SSE**: polling으로 충분. 0.8.x 이후 검토.
- **차트 라이브러리**: inline SVG 한 종류만. Chart.js/d3.js 도입 X.
- **멀티 인스턴스 집계**: 단일 `~/.codingbot/`만.
- **로그 검색/필터/소트 UI**: tail-only.
- **알림 (소리, desktop notify)**: 시각 변화로만.
- **status --watch 제거 또는 비활성화**: 0.6.0과 공존. 사용자가 둘 중 선택.
