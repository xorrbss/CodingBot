# CodingBot 0.4.0 — e2e 자동화 사이클 설계

- 작성일: 2026-05-01
- 베이스: `v0.3.0` (commit `e4196b8`)
- 사이클 가치 분류: **C — 검증 자동화 (회귀 보장)**
- 범위: `runner.run()` 멀티사이클 통합 e2e를 비용 0으로 자동화. fake `claude` 바이너리 + 시나리오 DSL + 3 시나리오 (S1/S2/S3) + `e2e_auto` 마커.
- 비범위: hook subprocess의 e2e 통합 (이미 unit/subprocess로 커버), transcript JSONL 시뮬레이션, cassette/record-replay, judge 캐싱, metrics export, S4(연속 abnormal)/S5(stop signal) 시나리오.

## 1. 동기

0.2.0(안전망) + 0.3.0(관측)을 합쳤지만, runner의 멀티사이클 흐름은 여전히 **수동 e2e (`tests/e2e/test_smoke.py`, `-m e2e`)** 로만 검증된다:

- 실제 `claude` CLI + Anthropic API 호출 ($0.10–$0.50/회) → CI 자동 실행 불가.
- 회귀 시점이 "사이클 release 직전 수동" 1회뿐 → runner 변경 시 즉시 검증 불가.
- handoff 멀티사이클, abnormal exit 회복 등 분기는 manual 1건이 커버 못 함.

0.4.0은 **runner ↔ claude ↔ handoff ↔ state** 통합 경로를 fake 바이너리로 대체해 비용 0 자동 회귀를 닫는다. 운영 코드(`codingbot/*`)는 무수정 — 변경은 `tests/e2e/`와 `pyproject.toml` 마커 추가에 한정.

## 2. 핵심 결정

| 항목 | 결정 |
|---|---|
| 모킹 경계 | `subprocess.run(["claude", msg])` (runner.py:127) — fake 바이너리로 PATH 치환 |
| Anthropic 처리 | hook 미호출 시나리오로 회피 (heuristics-only). fake_claude는 tool call을 트리거하지 않음 → 0.4.0 hook 통합 e2e 불필요 |
| 시나리오 스토리지 | JSON 파일. step 인덱스는 `$CODINGBOT_HOME/.e2e_step` (per-test 격리) |
| 시나리오 커버리지 | S1 happy_1_cycle / S2 handoff_multi / S3 abnormal_recover |
| 마커 정책 | 신규 `e2e_auto` (자동, 무료, 기본 수집). 기존 `e2e` (manual, $) 유지 |
| 운영 코드 변경 | 없음. `codingbot/*` LOC 변동 0, public API 변경 없음 |
| 의존 그래프 | 변경 없음 |
| transcript 시뮬레이션 | YAGNI. 0.4.0 시나리오는 transcript 미참조. 필요 시 0.5.0 |

## 3. 컴포넌트 명세

### 3.1 `tests/e2e/fake_claude.py` (신규)

#### 3.1.1 호출 계약

- 호출형: `claude <prompt>` (positional 1개 이상, 무시 가능). runner.py:127과 동일.
- env 입력:
  - `CODINGBOT_E2E_SCENARIO`: 시나리오 JSON 파일의 절대경로. 미설정 시 stderr 에러 + exit 90.
  - `CODINGBOT_HOME`: step 카운터/handoff 기록 위치 결정 (`paths.codingbot_home()`과 동일 규약 — env 우선).
- 출력: 부수효과만. stdout/stderr는 사용 안 함 (단, 에러 시 stderr 메시지).

#### 3.1.2 시나리오 JSON 스키마

```json
{
  "name": "happy_1_cycle",
  "steps": [
    {"exit_code": 0, "handoff": null},
    {"exit_code": 0, "handoff": null}
  ]
}
```

- `name`: str, 식별용. fake_claude는 사용 안 함 (사람용).
- `steps`: list[Step]. 1개 이상.
- `Step.exit_code`: int. 0=정상, 1/2/...=비정상.
- `Step.handoff`: str | null. str이면 `$CODINGBOT_HOME/handoff.md`에 기록 (`handoff.write` 동등 결과). null이면 기록 안 함.

#### 3.1.3 알고리즘

```
def main(argv):
    scenario_path = os.environ.get("CODINGBOT_E2E_SCENARIO")
    if not scenario_path or not Path(scenario_path).exists():
        print("[fake_claude] CODINGBOT_E2E_SCENARIO not set or missing", file=sys.stderr)
        sys.exit(90)
    scenario = json.loads(Path(scenario_path).read_text(encoding="utf-8"))
    home = Path(os.environ["CODINGBOT_HOME"])
    home.mkdir(parents=True, exist_ok=True)
    step_file = home / ".e2e_step"
    idx = int(step_file.read_text()) if step_file.exists() else 0
    steps = scenario["steps"]
    if idx >= len(steps):
        print(f"[fake_claude] step out of range: {idx} >= {len(steps)}", file=sys.stderr)
        sys.exit(91)
    step = steps[idx]
    if step.get("handoff") is not None:
        (home / "handoff.md").write_text(step["handoff"], encoding="utf-8")
    step_file.write_text(str(idx + 1), encoding="utf-8")
    sys.exit(int(step["exit_code"]))
```

- 이 모듈은 운영 코드를 import하지 않는다 (의존 없음, 표준 라이브러리만). PATH shim에서 직접 실행되므로 `codingbot.*` 패키지가 시각화되지 않을 수 있다는 점을 회피.
- LOC 예산: ≤ 80.

#### 3.1.4 자체 단위 테스트 (`tests/e2e/test_fake_claude.py`)

`pytest.mark.e2e_auto` 적용. 시나리오 1개 + step 2개로:

- 정상 step → exit 0, handoff 작성/생략, `.e2e_step` 증가 검증.
- step out-of-range → exit 91.
- env 미설정 → exit 90.
- 회귀 3건. fake_claude를 `subprocess.run([sys.executable, fake_claude_py, "prompt"])`로 직접 호출하여 검증 (PATH shim 우회).

### 3.2 `tests/e2e/conftest.py` (신규)

#### 3.2.1 `fake_claude_shim` fixture

- scope: function.
- 동작:
  1. `tmp_path / "bin"` dir 생성.
  2. OS별 shim 파일 생성:
     - **Windows** (`sys.platform == "win32"`): `bin/claude.cmd` 내용 `@python "<abs path>/fake_claude.py" %*`.
     - **POSIX**: `bin/claude` 내용 `#!/usr/bin/env python3` shebang + `import runpy; runpy.run_path("<abs path>/fake_claude.py", run_name="__main__")`. `chmod 0o755`.
  3. `monkeypatch.setenv("PATH", str(bin_dir) + os.pathsep + os.environ["PATH"])`.
  4. `assert Path(shutil.which("claude")).parent == bin_dir` — 시스템에 설치된 다른 `claude`가 가려지고 shim이 PATH에서 선택됨을 fail-fast 보장.
- 반환: shim의 dir 또는 path (현재는 미사용, 디버깅 편의).

#### 3.2.2 `e2e_scenario` fixture (factory)

- 호출: `e2e_scenario(scenario_dict)`.
- 동작:
  1. `tmp_path / "scenario.json"`에 JSON 직렬화.
  2. `monkeypatch.setenv("CODINGBOT_E2E_SCENARIO", str(scenario_path))`.
- 반환: scenario_path.

#### 3.2.3 의존

- 기존 `tmp_codingbot_home`(`tests/conftest.py`)을 재사용 — `CODINGBOT_HOME` 격리 + `config.load.cache_clear()` + `.e2e_step` 자동 격리.
- LOC 예산: ≤ 70.

### 3.3 `tests/e2e/test_runner_loop.py` (신규)

- 마커: `pytestmark = pytest.mark.e2e_auto`.
- 공통 import: `from codingbot.runner import run`, `from codingbot import state, paths, logger`.
- 각 테스트는 `tmp_codingbot_home`, `fake_claude_shim`, `e2e_scenario`를 사용.

#### 3.3.1 `test_s1_happy_1_cycle`

- 시나리오:
  ```python
  {"name": "happy_1_cycle", "steps": [
      {"exit_code": 0, "handoff": None},
      {"exit_code": 0, "handoff": None},
  ]}
  ```
- 검증:
  - `run("test prompt") == 0`.
  - `state.read()["cycles_this_run"] == 2`.
  - `paths.log_file()`의 JSONL에 `event=cycle_start` 라인 2회.
  - `paths.log_file()`의 JSONL에 `event=run_end, reason=final_check_returned_done` 1회.
  - `paths.handoff_file()` 미존재 (또는 빈 상태).

#### 3.3.2 `test_s2_handoff_multi`

- 시나리오:
  ```python
  {"name": "handoff_multi", "steps": [
      {"exit_code": 0, "handoff": "다음 작업: foo"},
      {"exit_code": 0, "handoff": None},
      {"exit_code": 0, "handoff": None},
  ]}
  ```
- 검증:
  - `run("initial") == 0`.
  - `state.read()["cycles_this_run"] == 3`.
  - `cycle_start` 라인 3회. iter#1의 `msg_preview`에 "initial" 포함, iter#2에 "다음 작업: foo" 포함, iter#3에 `FINAL_CHECK_PROMPT` 머리(예: "지금 코드 상태를") 포함. (`cycle_start` 로그는 subprocess 호출 *직전*에 기록되므로 인덱스 = 그 cycle의 입력 msg.)
  - `run_end.reason == final_check_returned_done`.

#### 3.3.3 `test_s3_abnormal_recover`

- 시나리오:
  ```python
  {"name": "abnormal_recover", "steps": [
      {"exit_code": 2, "handoff": None},
      {"exit_code": 0, "handoff": None},
      {"exit_code": 0, "handoff": None},
  ]}
  ```
- 검증:
  - `run("initial") == 0`.
  - `state.read()["cycles_this_run"] == 3`.
  - `log.jsonl`에 `event=claude_abnormal_exit, count=1` 1회.
  - `log.jsonl`에 `run_end.reason == final_check_returned_done` (회복 후 정상 종료).
  - `state` 카운터에 `claude_abnormal_exit` 카운터는 0.3.0에 없으므로 검증 안 함 (log 검증으로 충분).

#### 3.3.4 LOC 예산

- 헬퍼(예: `_read_log_events(home)`)를 conftest 또는 테스트 파일 상단에 두고 3 테스트가 공유. 전체 ≤ 150 LOC.

## 4. 데이터 흐름

```
pytest test_runner_loop.py::test_s2_handoff_multi
  ├─ tmp_codingbot_home: CODINGBOT_HOME=tmp/codingbot_home, log/state 격리
  ├─ fake_claude_shim:    PATH 앞에 tmp/bin/claude(.cmd|sh) 추가
  ├─ e2e_scenario(S2):    CODINGBOT_E2E_SCENARIO=tmp/scenario.json
  └─ runner.run("initial")
       loop iter 1:
         msg = "initial"  (handoff 없음)
         subprocess.run(["claude", "initial"])
            → shim → fake_claude.py(idx=0)
              ├─ scenario.steps[0] = {exit_code: 0, handoff: "다음 작업: foo"}
              ├─ write handoff.md "다음 작업: foo"
              ├─ write .e2e_step "1"
              └─ exit 0
         state.record_cycle()  → cycles=1
         handoff.exists() == True → final_check_pending=False
       loop iter 2:
         msg = handoff.read() = "다음 작업: foo"
         handoff.clear()
         subprocess.run(["claude", "다음 작업: foo"])
            → fake_claude(idx=1) → exit 0, no handoff
         state.record_cycle()  → cycles=2
         handoff.exists() == False → final_check_pending=True
       loop iter 3:
         msg = FINAL_CHECK_PROMPT
         subprocess.run(["claude", FINAL_CHECK_PROMPT])
            → fake_claude(idx=2) → exit 0, no handoff
         state.record_cycle()  → cycles=3
         handoff.exists() == False & final_check_pending → run_end final_check_returned_done
  └─ rc=0, assert state/log
```

## 5. 에러 처리

| 케이스 | fake_claude 동작 | 테스트가 잡는 방식 |
|---|---|---|
| `CODINGBOT_E2E_SCENARIO` 미설정 | stderr + exit 90 | `test_fake_claude.py` 1건 |
| 시나리오 파일 부재 | stderr + exit 90 | 동일 |
| step out-of-range | stderr + exit 91 | runner는 exit 91을 abnormal로 인식 → 시나리오 mismatch가 즉시 fail. `test_fake_claude.py` 1건 |
| step JSON 파싱 실패 | `json.JSONDecodeError` 상승 → exit 1 | 픽스처가 정상 JSON 직렬화하므로 실제 발생 안 함 |
| Windows에서 shim PATH 공백 | `claude.cmd`가 quote된 경로 사용 | `shutil.which("claude")` assert로 fixture가 즉시 fail |
| `codingbot` 패키지 import 누락 | fake_claude는 stdlib만 사용 | 비대상 |

운영 코드(`runner` 등)는 fake가 만든 exit code를 **실제 claude의 exit code와 동일하게 취급**한다. 이는 의도 — fake는 boundary를 emulate, runner는 unaware.

## 7. 위험 / 완화

| ID | 위험 | 완화 |
|---|---|---|
| R1 | Windows에서 `claude.cmd` shim이 PATH의 공백/한글 경로 처리 실패 | `tmp_path` 하위 `bin/`에서만 동작. shim 본문에서 경로 quote. fixture에서 `shutil.which("claude")` assert로 즉시 fail-fast |
| R2 | `tmp_codingbot_home` 내 `.e2e_step`이 다른 fixture와 충돌 | `paths.codingbot_home()`은 env 기반. tmp dir 격리되어 충돌 불가 |
| R3 | shim이 system `claude`를 가리지 못하고 뒤로 밀림 | PATH 앞쪽 prepend. fixture가 `which` 결과를 검증 |
| R4 | fake_claude가 `codingbot.*`를 import해서 운영 코드와 결합 | stdlib만 사용. import 정책을 명문화 (이 spec §3.1.3) |
| R5 | 시나리오가 실제 runner 동작 분기와 어긋남 (예: final-check 분기 오해) | spec §4 데이터 흐름을 step 단위로 명시. 테스트 assertion에서 cycles 수 + log event 시퀀스 모두 검증 |
| R6 | `e2e_auto`가 CI에서 `claude`(real) 환경의 system PATH로 새어 나감 | 모든 `e2e_auto` 테스트에 `fake_claude_shim` 필수 (강제). README에 명시 |
| R7 | 0.4.0이 "feature 없는 release"라는 인식 | release notes에 "test-infra-only cycle"로 명시. 다음 사이클(0.5.0) 후보 정리 |

## 8. 의존 그래프 영향

운영 코드 변경 없음 → 기존 그래프 그대로:

```
paths            (leaf)
logger          → paths
config          → logger, paths
heuristics      → config
transcript      → logger
llm_judge       → config
state           → config, logger, paths
handoff         → paths
runner          → handoff, logger, paths, state
cli             → config, install_hooks, paths, runner, state
install_hooks   (leaf)
hooks/auto_approve         → heuristics, llm_judge, logger, state, transcript
hooks/handoff_or_continue  → handoff, heuristics, llm_judge, logger, state, transcript
```

테스트 인프라 (fake_claude.py, conftest.py)는 `codingbot.*`를 import하지 않음 — 단방향 격리.
