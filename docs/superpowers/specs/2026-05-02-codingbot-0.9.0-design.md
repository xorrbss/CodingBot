# CodingBot 0.9.0 — judge OFF 모드 (P 사이클: privacy/cost)

**작성일**: 2026-05-02
**베이스**: `v0.8.0` (`1255fc6`)
**가치**: P — Anthropic API 호출 0건 옵션. ANTHROPIC_API_KEY 불필요. 비용 0. heuristic-only 동작.

## §1 동기

- 사용자가 ANTHROPIC_API_KEY 발급/관리/비용을 회피하고 싶음
- CLI judge(`claude -p`)로 대체 시도는 실측 결과 startup overhead 17~35초/호출로 production hook에 부적합 (handoff 19th update 참고)
- 즉시 사용 가능한 경로 = judge 분기 자체를 비활성화 + 기존 안전 폴백 경로 활용
- 기존 hook 구조에 이미 `JudgeError` → defer/allow_stop 안전 폴백이 회귀로 닫혀있음 (S6/S7/S8) → 새 코드 경로 거의 없이 재사용

## §2 결정 요약

| 항목 | 결정 | 근거 |
|---|---|---|
| 활성/비활성 | `Config.judge_enabled: bool = True` 신규 (default True = 기존 동작 보존) | 하위 호환 |
| 비활성 시 동작 | `llm_judge._call` 진입부에서 즉시 `JudgeError("judge disabled by config")` raise | 기존 `JudgeError` catch 경로 그대로 활용 — hook 코드 무변경 |
| PreToolUse 영향 | unknown tool은 `_defer_to_user` (judge="llm", reason="llm_failed") | S6 회귀와 동일 패턴 |
| Stop 영향 | unknown 응답은 `_allow_stop("llm_failed")` | S8 회귀와 동일 패턴 |
| API key 처리 | `judge_enabled=false` 시 `api_key_env` 환경변수 부재해도 OK (호출 자체가 안 일어남) | KISS |
| heuristic 분기 | 무영향 — safe_tools 자동승인, risky_patterns/categories 차단, is_clearly_continuing/done 그대로 | 기존 코드 |
| 카운터 | `judge_call_total`/`judge_timeout_total`/`judge_error_total` 는 호출되지 않으므로 모두 0 유지 | 자연스러움 |
| 운영 코드 변경 | config.py + llm_judge.py만 (~5 LOC) | 최소 변경 |

## §3 외부 인터페이스

- `Config` 신규 필드: `judge_enabled: bool = True`
- `Config.api_key_env`는 그대로(호환). `judge_enabled=false` 시 무의미해질 뿐 제거하지 않음.
- public API breaking change 없음. 기존 사용자(judge_enabled 미지정)는 default True로 0.8.0 동작 100% 동일.
- config.yaml 신규 키 1개. 미지정 시 기본값.
