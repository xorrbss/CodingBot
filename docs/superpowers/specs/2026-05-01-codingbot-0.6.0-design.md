# CodingBot 0.6.0 — `status --watch` (S 사이클) 설계

- 작성일: 2026-05-01
- 베이스: `v0.5.0` (commit `24f6cd1`)
- 사이클 가치 분류: **S — 운영 가시성 (한 화면에서 라이브로 본다)**
- 범위: `codingbot status --watch [--interval N] [--tail N]` — 기존 `status` 출력을 주기적으로 재출력하고 `paths.log_file()`의 마지막 N줄을 함께 표시한다.
- 비범위: 출력 포맷 자체 변경, lock pid 표시 enhancement, 색상/TUI 라이브러리, log 라인 파싱/요약, watch 중 키 입력 처리.

## 1. 동기

0.3.0에서 `status`가 12개 카운터를 5개 섹션으로 노출했다. 그러나 운영 중에는 다음 패턴이 반복된다:

```
codingbot status; sleep 3; codingbot status; sleep 3; ...
codingbot tail-log -n 20; codingbot status; ...
```

0.5.0까지 hook 분기까지 모두 자동 회귀로 닫혔으므로, 다음 1마일은 **사람이 한 화면에서 사이클이 도는 모습을 본다**이다. `status --watch`는 이걸 80% 만족시키는 가장 작은 변경이다.

## 2. 핵심 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 재출력 방식 | `os.system("cls"/"clear")` + 기존 `_cmd_status` body 그대로 한 번 더 호출 | KISS. 기존 출력 포맷 유지 → 단위 회귀 회귀 영향 0. curses/ANSI 도입은 의존/Windows 호환 비용 대비 가치 낮음. |
| log tail 위치 | watch 화면 하단에 별도 섹션 (`=== Last log ===`) | 기존 `tail-log` 동등 정보를 같은 화면에 결합. `_read_log_tail` 1 헬퍼 재사용. |
| 인터벌 | `--interval N` (default 1초, int) | 사람 눈에 충분히 빠르고 부담 없음. 0.x에서는 다양화 불요. |
| tail 라인 수 | `--tail N` (default 10, int) | 한 화면 안에 carrier 정보까지 다 보이는 기본값. |
| 종료 | `KeyboardInterrupt` (Ctrl-C)에 의한 깨끗한 종료 (rc 0) | 시그널 핸들러나 signal 모듈 도입 불필요. `try/except`만으로 충분. |
| watch 분기 위치 | `_cmd_status` 첫 줄에서 `args.watch`면 `_watch_status(args)`로 위임 | 기존 1회성 호출 경로 무영향. `--watch` 미지정 시 코드 경로 동일. |
| 호출자 알림 | watch 헤더 `--- CodingBot Status (refresh Ns) --- YYYY-MM-DD HH:MM:SS ---` 한 줄 추가. body는 기존 동일. | 사용자 mock과 정합. 새 정보는 시간만. |
| log 파일 미존재 | `=== Last log ===` 아래 빈 줄 (메시지 출력 안 함) | watch 사이클 중 log이 막 생기는 순간을 매 프레임 메시지로 점유하지 않음. 기존 `tail-log` 의 `[codingbot] no log yet`은 1회성 명령에만 의미. |

## 3. 컴포넌트 명세

### 3.1 `codingbot/cli.py` 변경

#### 3.1.1 신규 헬퍼: `_read_log_tail(n: int) -> List[str]`

```python
def _read_log_tail(n: int) -> List[str]:
    """log.jsonl의 마지막 n줄을 list[str]로 반환 (파일 없으면 빈 리스트)."""
    p = paths.log_file()
    if not p.exists():
        return []
    return p.read_text(encoding="utf-8").splitlines()[-n:]
```

- 위치: `_cmd_tail_log` 위. 동일 파일 read 책임이지만 반환 타입이 달라 별도 함수로 분리 (재사용 1곳: `_watch_status`).
- 0.5.0까지 log은 단조 증가 + 작은 사이즈 (cycle당 수 라인) → 전체 read 후 slice가 충분히 KISS. tail-style 64KB chunk read는 transcript와 달리 불필요 (yagni).

#### 3.1.2 신규 함수: `_watch_status(args) -> int`

```python
def _watch_status(args) -> int:
    import os, time
    from datetime import datetime
    interval = args.interval
    tail_n = args.tail
    try:
        while True:
            os.system("cls" if os.name == "nt" else "clear")
            ts = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
            print(f"--- CodingBot Status (refresh {interval}s) --- {ts} ---")
            _print_status_body()
            print("\n=== Last log ===")
            for line in _read_log_tail(tail_n):
                print(line)
            time.sleep(interval)
    except KeyboardInterrupt:
        return 0
```

- 종료: Ctrl-C → rc 0.
- `_print_status_body()`: 기존 `_cmd_status` body의 print 블록을 함수로 분리. 기존 `_cmd_status`는 `--watch` 분기 후 `_print_status_body()` + `return 0`.

#### 3.1.3 `_cmd_status` 분기

```python
def _cmd_status(args: argparse.Namespace) -> int:
    if getattr(args, "watch", False):
        return _watch_status(args)
    _print_status_body()
    return 0
```

#### 3.1.4 argparse: `status` subparser 옵션 추가

```python
status.add_argument("--watch", action="store_true", help="주기적으로 화면을 갱신하며 표시")
status.add_argument("--interval", type=int, default=1, help="갱신 주기(초). default 1")
status.add_argument("--tail", type=int, default=10, help="하단 log 표시 줄 수. default 10")
```

### 3.2 회귀 (단위)

`tests/unit/test_cli.py`에 추가:

- `test_status_watch_runs_one_iteration_then_exits_on_interrupt` — `time.sleep`을 `KeyboardInterrupt`로 patch + `os.system` no-op patch → `cli.main(["status", "--watch", "--interval", "1", "--tail", "3"])`가 rc 0, stdout에 `refresh 1s` 헤더 + 기존 `=== Cycle ===` + `=== Last log ===` 모두 포함.
- `test_status_watch_default_args_when_unspecified` — argparse가 `interval=1`, `tail=10`을 기본값으로 채우는지 (위 테스트 변형).

## 5. 비범위 (명시)

- **lock pid 표시**: 사용자 mock에는 `(pid 13422)`가 보이지만, `_cmd_status` 출력 포맷 자체를 건드리는 변경이라 별 task로 분리. 0.6.0 S 사이클 범위 외.
- **TUI / curses / ANSI 색상**: 의존 도입 + Windows 콘솔 호환 비용. 80% 만족에는 불필요.
- **log line 파싱·요약·필터**: log 라인은 raw로만 표시. JSON 파싱은 별도 사이클.
- **watch 중 키 입력**: Ctrl-C로 종료만. r/q 같은 인터랙션 없음.
