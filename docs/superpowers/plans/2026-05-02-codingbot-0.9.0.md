## 작업 단위 (atomic commits)

### Task 1 — `Config.judge_enabled` field

- 파일: `codingbot/config.py`, `tests/unit/test_config.py`
- 변경:
  - `Config` dataclass에 `judge_enabled: bool = True` 추가 (기존 필드 사이 적절한 위치 — `judge_model` 근처)
  - `load()` whitelist 튜플에 `"judge_enabled"` 추가
- 회귀:
  - `test_default_judge_enabled_true` — default Config에서 `judge_enabled is True`
  - `test_load_yaml_overrides_judge_enabled` — yaml에 `judge_enabled: false` 작성 후 `load().judge_enabled is False`
- 커밋 메시지: `feat(config): add judge_enabled flag (default True, backward-compat)`

### Task 2 — `llm_judge._call` 진입부 비활성 체크

- 파일: `codingbot/llm_judge.py`, `tests/unit/test_llm_judge.py`
- 변경:
  - `_call(system, user)` 진입부 fault-inject 검사 직후 또는 직전에 `cfg = config.load()`(이미 fault 검사 후 `_client()` 안에서 부르고 있으나 CALL 직전 검사가 더 깔끔. fault-inject 검사 다음에 추가) `if not cfg.judge_enabled: raise JudgeError("judge disabled by config")`
  - 정확한 위치: `fault = os.environ.get(...)` 분기 다음, `_client()` 호출 전.
- 회귀:
  - `test_evaluate_tool_safety_raises_when_judge_disabled` — config에 `judge_enabled: false` 작성 후 `evaluate_tool_safety("Bash", {"command":"x"}, "")` → `JudgeError` raise (API 호출 없이)
  - `test_classify_raises_when_judge_disabled` — 동일 패턴, `classify([])` → `JudgeError`
  - 두 회귀 모두 `_client()`가 호출되지 않아야 함을 검증 (mocker.patch + assert_not_called)
- 커밋 메시지: `feat(llm_judge): short-circuit when judge_enabled=false (no API call)`
