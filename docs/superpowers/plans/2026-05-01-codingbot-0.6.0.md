# CodingBot 0.6.0 — `status --watch` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 한 화면에서 `codingbot status` + 최근 log 라인을 주기적으로 갱신해 운영 중 사이클이 도는 모습을 라이브로 본다.

**Architecture:** `_cmd_status`를 `--watch` 분기 + `_print_status_body()` 분리. `_watch_status`는 `os.system("cls"/"clear")` + 헤더 + body + `_read_log_tail()` + `time.sleep(interval)` 루프. Ctrl-C(`KeyboardInterrupt`) 시 rc 0. 새 의존 없음 (stdlib만).

**Tech Stack:** Python 3.11, stdlib (`os`, `time`, `datetime`), pytest 8+, pytest-mock.

**Spec:** `docs/superpowers/specs/2026-05-01-codingbot-0.6.0-design.md`

**Base:** `v0.5.0` (`24f6cd1`).

## Risk

- watch 루프 안에서 `os.system("cls")`가 테스트 환경에서 콘솔을 더럽힐 가능성 → 단위 테스트에서 `mocker.patch("os.system")`로 차단.
- `time.sleep`을 patch하지 않으면 테스트가 멈춤 → 반드시 patch 후 `KeyboardInterrupt` side_effect.
- `paths.log_file()`이 매우 큰 경우(수십 MB)에 전체 read는 비효율 — 0.6.0에서는 yagni. 로그 회전 정책이 들어오면 다음 사이클에서 tail-style read 도입.
